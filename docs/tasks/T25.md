## T25: Pricing page and payments (Razorpay + Stripe)
Goal: a free learner can upgrade, and premium unlocks every lesson (Product spec §2.3; System design §6, §7).
Needs: Razorpay test-mode keys in env (names in .env.example), created by the user. Stripe is deferred (decided 15 Nov).
Files: packages/payments/src/** (razorpay.ts, stripe.ts, index.ts), packages/payments/test/**,
       apps/web/app/(marketing)/pricing/page.tsx (+ client component and css), apps/web/app/api/checkout/route.ts,
       apps/web/app/api/webhooks/razorpay/route.ts, apps/web/app/api/webhooks/stripe/route.ts,
       apps/web/app/api/billing/manage/route.ts, apps/web/package.json, pnpm-lock.yaml
Interface (frozen): PaymentProvider and providerFor exactly as SPEC §6; API routes as SPEC §5 and §15.
Rules:
- Prices only from apps/web/lib/plans.ts. Currency from x-vercel-ip-country (IN → INR) with a toggle.
- Stripe deferred (option 2, decided 15 Nov): build Razorpay fully; stripe.ts implements PaymentProvider but
  createCheckout throws "stripe_unavailable" and verifyWebhook returns false. USD visitors see USD prices and
  "Coming soon in your region" with no checkout button; the toggle lets them switch to INR and pay with Razorpay.
  /api/checkout with currency USD → 409 {error:"region_unavailable"}. The Stripe webhook route returns 503.
- Plans: monthly and annual only. Lifetime is not sold for now (decided 15 Nov, decision 13): no lifetime option on
  the pricing page or in checkout. Keep the frozen Plan type as is (it still includes 'lifetime').
- Webhooks: verify signature on the raw body → insert event_id into webhook_events (duplicate → 200, no-op) →
  upsert subscriptions → recompute profiles.is_premium. Never trust the client for premium.
- Checkout from the server only; secrets only via process.env on the server; never call providers from the client.
- /api/billing/manage: Stripe customer portal URL, or cancel the Razorpay subscription.
- Pricing page layout per §2.3 (annual first with "Most popular", Upgrade, "Cancel any time · full refund if unhappy").
Done when: unit tests for both providers' signature checks, event mapping and idempotency; a test-mode purchase on
the preview grants premium and unlocks lesson 3; cancel works; checks pass.
