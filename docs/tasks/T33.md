## T33: AI explanations — 20 new Gemini calls a day
Goal: enforce T26's frozen limit ("20 uncached calls a day per user or IP") so the Gemini key can go live.
Approved by the owner 16 Nov: a call-log table only (per-user ratings stay deferred).
Files: supabase/migrations/0003_explain_calls.sql (new), apps/web/lib/explain.ts, apps/web/lib/explain.test.ts,
       apps/web/app/api/explain/route.ts, apps/web/app/api/explain/route.test.ts, .env.example
Schema (0003):
- table explain_calls (id bigint generated always as identity primary key, caller text not null,
  called_at timestamptz not null default now()); index on (caller, called_at).
- RLS enabled with no policies (only the service-role admin client reads/writes it), like the other
  server-only tables in 0001.
Rules:
- caller = SHA-256 hex of "user:<user id>" when signed in, else of "ip:<first x-forwarded-for entry>:<EXPLAIN_IP_SALT>".
  Never store the raw id or IP. EXPLAIN_IP_SALT is a server env var (add the name to .env.example); if it is
  missing, signed-out calls are refused with 503 ai_unavailable (signed-in calls still work).
- Only a cache MISS that is about to call Gemini counts: before the call, count rows for the caller with
  called_at ≥ the start of today in IST (Asia/Kolkata); 20 or more → 429 {error:"limit"} and no Gemini call.
  Otherwise insert the row, then call Gemini (a failed Gemini call still counts — it may still cost).
  Cache hits never count and never insert.
- Count failure or insert failure → 503 ai_unavailable (fail closed; never call Gemini unmetered).
- Remove the T26 TODO; keep the pure limit helper and test it (IST day start, boundary 19/20/21).
- The Player shows a friendly line for 429: "You've used today's AI explanations. They reset at midnight."
  — only if Player.tsx needs a change to show it; then add Player.tsx (drawer slot only) to Files.
- API contract unchanged except the documented 429.
Done when: tests pass (at least 12 new: hashing, IST day start, 19 allowed / 20 refused, hits don't count, misses
insert before Gemini, count/insert failure → 503, missing salt for signed-out → 503, signed-in without salt works);
`pnpm typecheck && pnpm test && pnpm validate-content` pass; build succeeds; the owner runs 0003 in Supabase.
