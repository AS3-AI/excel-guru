## T32: Razorpay checkout sends total_count
Goal: live test (16 Nov) showed "checkout_unavailable": POST /v1/subscriptions requires `total_count`, which we
never sent, and the route hid Razorpay's error.
Files: packages/payments/src/index.ts, packages/payments/test/payments.test.ts, apps/web/app/api/checkout/route.ts
Rules:
- Send `total_count`: monthly 120, annual 10 (the subscription renews until cancelled; Razorpay needs a cap).
- On a non-2xx response throw an error whose message includes the HTTP status and Razorpay's
  `error.code`/`error.description` (never the key, secret or request headers); the checkout route logs that
  message with console.error and still returns 503 {error:"checkout_unavailable"} to the client.
- PaymentProvider interface unchanged. Tests first.
Done when: tests pass; `pnpm typecheck && pnpm test && pnpm validate-content` pass; a live test checkout opens Razorpay.
