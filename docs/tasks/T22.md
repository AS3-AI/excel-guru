## T22: Merge race — points awarded twice
Goal: a lesson can never earn points twice in one IST day, however requests arrive (decision: replay rule A in T19).
Bug seen 15 Nov: two concurrent /api/progress/merge calls after sign-up both awarded Intro (90 instead of 45).
Files: supabase/migrations/0002_points_once_per_day.sql (new), apps/web/lib/local-progress.ts,
       apps/web/lib/local-progress.test.ts, apps/web/lib/progress.ts, apps/web/lib/progress.test.ts,
       apps/web/app/api/progress/route.ts, apps/web/app/api/progress/merge/route.ts
Rules:
- Migration 0002 (idempotent, runs on a database that already has 0001 and data):
  add lesson_completions.ist_day date; backfill it from completed_at in Asia/Kolkata; set existing duplicate
  (user_id, lesson_id, ist_day) rows with points > 0 to points 0 except the earliest; then
  create unique index on (user_id, lesson_id, ist_day) where points > 0. ist_day not null after backfill.
- Routes: insert lesson_completions with ist_day (IST date of "now") and the computed points first. If the insert
  fails with a unique violation (23505), insert again with points 0 and write no points_log row; the response's
  points is 0. Every other write behaves as in T19. Keep the existing pre-check (it avoids most violations).
- Client: mergeLocalProgress() is single-flight — concurrent calls share one in-flight request and promise;
  React StrictMode double effects and the dashboard + player call sites therefore send one request.
- Pure logic tests first: single-flight (two concurrent calls → one fetch, both resolve the same result; a later
  call after completion makes a new request); the route's unique-violation fallback via a pure helper.
Done when:
- tests pass, including the cases above
- Claude runs the migration SQL on a scratch check (syntax) and the user runs it in Supabase; then two concurrent
  merges for the same lesson award points once (verified live)
- `pnpm typecheck && pnpm test && pnpm validate-content` pass; `pnpm --filter web build` succeeds; no other files changed
