## T36: Free tier counts lessons opened
Goal: SPEC §2.3 — "a free account gets 2 lessons in total, and Intro counts … opening any 3rd lesson without
premium redirects to /pricing". Today only *completed* lessons count, so a free user who finished Intro can open
every lesson. Owner approved a lesson_opens table (16 Nov).
Files: supabase/migrations/0004_lesson_opens.sql (new), apps/web/lib/access.ts, apps/web/lib/access.test.ts,
       apps/web/app/(app)/lesson/[id]/page.tsx
Schema (0004): lesson_opens (user_id uuid references auth.users on delete cascade, lesson_id text not null,
  opened_at timestamptz not null default now(), primary key (user_id, lesson_id)); RLS on, no policies.
Rules:
- A free (non-premium, non-group-premium) signed-in user's "used" lessons = lessons they opened ∪ completed.
  Opening lesson X is allowed if X is already used, or fewer than 2 lessons are used; otherwise paywall.
- Only the lesson PAGE records an open (insert … on conflict do nothing), and only after the decision allows it,
  and only for free users (premium opens aren't recorded). Recording failure → still render (don't lock a
  learner out because of a logging error) but never count the open as allowed for a 3rd lesson.
- Every other caller (progress, merge, workbook, access route, explain) uses the same decision with the opened
  lessons included, read-only — they never insert.
- Signed out: Intro only (unchanged). Premium / group premium: everything (unchanged). Replays always allowed.
- Existing users need no backfill: completed lessons already count.
Done when: tests first (decision with opened/completed/both, 0/1/2 used, replays, premium, group premium, signed
out; page records only allowed free opens; insert failure path; other routes don't insert); `pnpm typecheck &&
pnpm test && pnpm validate-content` pass; build succeeds; owner runs 0004 in Supabase; checked in the browser
with a free test account (Intro + one lesson open, a third → /pricing).
