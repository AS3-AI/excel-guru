## T43: `/learn/[function]` article template
Goal: SEO articles that send readers into practice (SPEC Product §13). This card builds the template and one
sample article; the other articles are content (C14), written later as data files only.
Files: apps/web/app/(marketing)/learn/[fn]/page.tsx (new), apps/web/app/(marketing)/learn/page.tsx (new index),
       apps/web/app/(marketing)/learn/learn.css (new), apps/web/lib/learn.ts (new), apps/web/lib/learn.test.ts (new),
       content/learn/sum.json (new sample), scripts/validate-content.ts (validate content/learn too),
       scripts/validate-content.test.ts
Article format (content/learn/<slug>.json): { slug, fn, title, description (≤160 chars), syntax,
  args: [{ name, required, text }], sections: [{ heading, text (rich text as lessons use), grid? (≤7×8, null for
  empty), formula?, result? }], lessonId (must exist in content/order.json), related: [slug] }.
Rules:
- Static pages: generateStaticParams over content/learn; generateMetadata sets title/description/OG basics.
- Render sections with the existing RichText component; grids as a simple read-only table (no Sheet editing).
- A sticky bottom bar "Continue to <fn> practice →" deep-links to /lesson/<lessonId>; it must not cover the
  footer on a phone (375 px). Colours only from tokens.css. Public pages: no auth.
- validate-content checks every article: schema, lessonId exists, related slugs exist, each formula/result pair
  evaluates to result with the engine on the section's grid.
- The sample article (SUM) is written in our own words; never copy docs/teardown.md.
- Make sure content/learn is traced into the build (outputFileTracingIncludes already covers content/**).
Done when: tests first (loader, validation pass/fail cases); `pnpm typecheck && pnpm test && pnpm validate-content`
pass; build lists /learn and /learn/sum as static; checked at 375 px in the browser.
