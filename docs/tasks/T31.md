## T31: INDEX and MATCH follow Excel
Goal: INDEX gives Excel's answers for one-row ranges and for a whole row or column (bugs found 15 Nov while
preparing the Index Match module: =INDEX(A1:D1,2) returns #REF! instead of B1; =INDEX(C2:C5,0),
=INDEX(A2:D5,,2) and =INDEX(A2:D5,3,0) return one value instead of spilling).
Files: packages/engine/src/functions.ts, packages/engine/test/functions.test.ts
Rules (Excel 365, array form only — the reference form with several areas is out of scope):
- INDEX(array, row_num, [column_num]). A one-row array with a single index uses it as the column:
  =INDEX(A1:D1,2) → B1. A one-column array with a single index uses it as the row.
- row_num 0 or omitted (=INDEX(A2:D5,,2)) → the whole column, which spills down; column_num 0 → the whole row,
  which spills right; both 0 → the whole array spills.
- Out of range (row_num > rows, column_num > columns, or a second index on a one-row/one-column array that
  isn't 1) → #REF!; negative or non-numeric → #VALUE!; numbers are truncated (2.9 → 2).
- An error passed as row_num/column_num propagates. A blank cell in the result returns 0 (as a formula
  referring to a blank cell does in Excel); a spilled blank shows as 0 too.
- INDEX with MATCH keeps working exactly as today (=INDEX(C2:C5,MATCH("Bo",A2:A5,0)) → 350).
- MATCH (our own code, not formula.js): match_type 0 exact (wildcards `*` `?` `~`, case-insensitive);
  1 or omitted → the position of the LAST value of the lookup's type that isn't above it (the same rule as
  VLOOKUP's approximate match, so an unsorted list gives Excel-like wrong answers, never a silent exact hit);
  -1 → the last value of that type that isn't below it; nothing qualifies → #N/A. A range that is neither one
  row nor one column → #N/A. Positions count from the range's first cell.
