## T13: Element-wise functions over arrays
Goal: single-value functions and IF work across ranges and arrays, spilling as in Excel 365, so the Array formulas
lessons can use =IF(B2:B6>85,"Pass","Fail"), =LEN(A2:A6), =ROUND(B2:B6*1.15,1). Read docs/SPEC.md §3 first. Runs after T6.
Files: packages/engine/src/functions.ts, packages/engine/src/evaluator.ts,
       packages/engine/test/lift.test.ts (new), packages/engine/test/evaluator.test.ts
Rules:
- A function argument that expects a single value but receives an array is applied element by element and the results
  form an array (which then spills). Arrays in several such arguments pair up with the existing broadcasting rules
  (a single row/column repeats; mismatched cells → #N/A).
- Arguments that take ranges keep receiving the whole 2-D array (SUM, AVERAGE, COUNT*, *IF(S) ranges, SUMPRODUCT,
  VLOOKUP/HLOOKUP/XLOOKUP/INDEX/MATCH tables, UNIQUE/FILTER/SORT, TEXTJOIN, CONCAT, etc.). Keep an explicit per-function
  table of which argument positions are "range" vs "single"; a function not in the table defaults to single.
- IF with an array condition evaluates per element; it stays lazy for a scalar condition.
- Fix the silently wrong scalars found in the T6 review: =UPPER(A1:A3) must spill, not return "AB,CDE,F";
  =NOT(B1:B3>1) and =ISNUMBER(A1:A2) must spill, not return FALSE.
- Pure TypeScript; tests first; keep every existing engine test passing (including timezone tests).
Done when:
- tests (at least 40) cover IF, LEN, ROUND, ABS, UPPER, NOT, ISNUMBER, TEXTBEFORE over arrays, =SUM(LEN(A1:A3)),
  broadcasting across two array arguments, and that range-taking functions are unchanged
- `pnpm typecheck && pnpm test && pnpm validate-content` pass; no other files changed
