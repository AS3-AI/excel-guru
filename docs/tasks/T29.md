## T29: IS functions must see errors
Goal: ISERROR, ISERR, ISNA (and ERROR.TYPE) return the right answer for error values (bug found 15 Nov:
=ISERROR(10/0) and =ISNA(NA()) return FALSE; IFERROR works).
Files: packages/engine/src/functions.ts, packages/engine/src/evaluator.ts, packages/engine/test/functions.test.ts
Rules:
- ISERROR(x): TRUE for any error. ISERR(x): TRUE for any error except #N/A. ISNA(x): TRUE only for #N/A.
  ERROR.TYPE: #NULL! 1, #DIV/0! 2, #VALUE! 3, #REF! 4, #NAME? 5, #NUM! 6, #N/A 7 (others → #N/A). These functions
  receive the error instead of propagating it — for a direct argument, a cell reference to an error cell, and an
  error produced inside the argument (=ISERROR(1/0)). With a range argument they behave as Excel 365 (spill).
- Other IS functions (ISNUMBER, ISTEXT, ISBLANK, ISLOGICAL, ISNONTEXT, ISEVEN, ISODD) given an error return FALSE
  (they don't propagate it), as Excel does — except ISEVEN/ISODD, which propagate.
