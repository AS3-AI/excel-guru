## T26: AI explanations (Gemini, cached)
Goal: a wrong answer shows a short AI explanation in the drawer, cached and rated (Product spec §7, decision 23).
Needs: GEMINI_API_KEY and GEMINI_MODEL in env (server only), created by the user.
Files: apps/web/app/api/explain/route.ts, apps/web/app/api/explain/[id]/rate/route.ts, apps/web/lib/explain.ts,
       apps/web/lib/explain.test.ts, apps/web/app/(app)/lesson/[id]/Player.tsx (drawer slot only), player.css
Interface (frozen, SPEC §5): POST /api/explain {lessonId, stepId, input} → {id, text, cached};
  POST /api/explain/[id]/rate {helpful} → {ok}; 20 uncached calls a day per user or IP.
Rules: the server builds the prompt from the lesson file (never from the client); normalise the wrong input;
cache by (lesson, step, normalised input) with score ≥ 0, best first; 👍/👎 ±1; below 0 → not served; under 80
words; never reveal another lesson's answer; typing dots while loading; "AI can be wrong" disclaimer.
Done when: tests for normalisation, cache hit/miss, rate limit, score retirement; a live wrong answer shows an
explanation and a second identical wrong answer is served from cache; checks pass.
