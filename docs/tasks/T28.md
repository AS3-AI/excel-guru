## T28: Engine fixes — error criteria and whole-row ranges
Goal: two Excel mismatches found while writing lessons (build log "Open bugs").
Files: packages/engine/src/{tokenizer,parser,address,evaluator,sheet,functions}.ts, packages/engine/test/**,
       apps/web/components/grid/refs.ts, apps/web/components/grid/refs.test.ts
Rules:
- Error criteria: in the *IF(S) family, a criteria argument that evaluates to an error (e.g. an unknown name
  `Hike` → #NAME?, or a reference to an error cell) makes the function return that error, as Excel does.
  A criteria *string* naming an error ("#N/A") keeps matching error cells (T12 behaviour).
- Whole-row ranges: `3:3`, `2:5`, `$3:$3` parse and evaluate like Excel, clipped to the grid's used columns (the
  same way whole columns are clipped to used rows); they work in SUM, COUNT, the *IF(S) family, spills, recalc
  dependencies and cycle detection. A lone number is still a number (`=3`), and `A1:3` style mixes are errors as Excel.
- Grid: re-enable Space-after-row-number in point mode (T18 turned it off because the engine couldn't parse rows):
  `wholeLineRef` produces `3:3` again, with tests.
- Keep every existing engine, grader and grid test passing (incl. timezone tests). Tests first.
Done when: tests cover both fixes (≥ 25 new); `=SUMIF(A2:A5,Hike,B2:B5)` → #NAME?; `=SUM(2:2)` over a row sums it;
