## T19: Progress API and saving progress
Goal: finishing a lesson saves progress on the server (signed in) or in localStorage (signed out), as in System design §2.
Read docs/SPEC.md §2, §5, §7 and Product spec §7 and §15 first. Runs after T15 and T16.
Files: apps/web/app/api/progress/route.ts, apps/web/app/api/progress/merge/route.ts,
       apps/web/app/api/progress/reset/route.ts, apps/web/app/api/dashboard/route.ts (all new),
       apps/web/lib/progress.ts (new, pure scoring + re-grading), apps/web/lib/progress.test.ts (new),
       apps/web/lib/local-progress.ts (new), apps/web/lib/local-progress.test.ts (new),
       apps/web/app/(app)/lesson/[id]/Player.tsx
Interface (frozen, SPEC §5):
  POST /api/progress {lessonId, attempts} → {points, streak, firstTryAccuracy, nextLessonId}
  POST /api/progress/merge {lessons: [{lessonId, attempts}]} → {merged}
  POST /api/progress/reset → {ok}   (keeps points and streak)
  GET  /api/dashboard → {modules: [{id, done, total, tag}], nextLessonId, points, streak, dailyTrend}
Rules:
- The server loads the lesson JSON and re-grades every attempt with packages/grader (never trusts the client); a lesson
  only completes if the re-graded correct count reaches requiredCorrect. First-try accuracy = share of steps answered
  right first time; points = 10 × difficulty per correct answer, +50% if first try, 0 after Show Answer (decision 20).
- Writes with the service-role client (server-only): step_attempts, lesson_progress (upsert, times_completed +1),
  lesson_completions (append, with group_id and cohort from profiles), points_log, streaks (IST day boundary:
  yesterday → +1, same day → unchanged, older → 1).
- Replay rule (decided 15 Nov, option A): a lesson earns points only on its first completion per IST day; later
  completions that day still save progress and a completion row, with 0 points.
- Reset clears lesson_progress only. Status tag per lesson (§7): first-try accuracy < 50% → low, else last completed
  ≥ 14 days ago → practice, else good. dailyTrend may be [] until Phase 4.
- Signed out: the player saves attempts under localStorage key eg_progress. Provide a client helper
  mergeLocalProgress() that posts them to /api/progress/merge (which re-grades and saves) and clears the key;
  calling it from the sign-up/sign-in flow is T20's job.
- Validate request bodies; 401 when signed out (except where the contract says any); never log secrets.
- Pure logic (re-grading, accuracy, points, streak transitions, status tags) in progress.ts with tests first.
Done when:
- progress tests (at least 30) cover re-grading a forged "correct" attempt as wrong, accuracy, points incl. Show Answer,
  streak transitions across IST midnight, and tags
- locally against the dev/prod Supabase in .env.local: finishing /lesson/intro signed in writes the rows; signed out
  stores eg_progress and merges after sign-in; reset keeps points and streak
- `pnpm typecheck && pnpm test && pnpm validate-content` pass; `pnpm --filter web build` succeeds; no other files changed
